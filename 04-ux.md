# 04 — UX and interaction

The product is two moments (21:30 on a phone, Sunday on a desktop). This file specifies exactly
what happens in each and how fast it has to happen.

---

## 1. Routes

| Route | Screen | Purpose |
|---|---|---|
| `/` | Today | Log today. Score header. Weakest link. |
| `/?d=YYYY-MM-DD` | Day detail | Read or correct a past day (read-only beyond 30 days) |
| `/week` | Week | Weekly metrics, day grid, this week vs last |
| `/trends` | Trends | 30/90-day sparklines per metric, insights cards |
| `/settings` | Settings | Targets, weights, visibility, sync, data, theme |
| `/onboarding` | Setup wizard | 9 fields, 3 minutes, once |

Top bar: wordmark `north`, then `TODAY · WEEK · TRENDS`. Settings is a text link at the right on
desktop, and a `⌘,`-style text row at the bottom of every screen on mobile. No icons.

```
│  Sleep 7.4h · Steps 8.2k · Daylight 34m ·    │
│  Leaks 71m · Weight 81.2kg −0.4%/wk          │
│                                              │
│  WEAKEST LINK                                │  ← 72 px

└──────────────────────────────────────────────┘
```

**Height budget:** 56 + 24 + 116 + 32 + (9 × 52 = 468) + 64 + 72 = **832 px**.
On a 390 × 844 standalone PWA the usable height is ≈ 780 px, so the *default* view shows the
first six rows plus the auto strip and hides the rest behind a one-line `+ 3 more` expander.
The acceptance criterion is: with 9 unlogged rows, the last unlogged row is reachable without
scrolling **or** the expander is visibly the single next thing. Test this in Playwright.

**Ordering rule.** Rows render in this order, always:

1. Unlogged manual metrics, in registry order.
2. Logged manual metrics, dimmed (`--ink-muted`), with the value shown.
3. Weekly metrics due this week (only if not yet met).
4. The `+ n more` expander.
5. The automatic strip.

Nothing re-orders while you are tapping. Logging a row does not move it under your finger until
the next visit to the screen. Fluidity beats cleverness.

## 3. Widgets

Component names match `06-architecture.md` §2.

| Widget | Used by | Rendering | Interactions |
|---|---|---|---|
| `TriState` | creatine, alcohol, learned, read, adult, invested | Three 36 × 36 cells: `·` `✓` `✗` | One tap sets the state. Tap `·` to clear. |
| `ChoiceRow` | protein, greens, strength_sessions, daylight_days | Absolute-value cells (`0 1 2 3 4 5`) | Tap a cell → that value. 1 tap, never incremental. |
| `Segmented` | deep_blocks | `0 1 2 3+` | Tap. `3+` stores `3.5`. |
| `Bins` | phone_total, social_min | 4–5 labelled cells sized to content | Tap. Stores the bin's numeric value. |
| `NumberField` | sleep_hours, steps, weight_trend, distraction_min, savings_rate, sleep_consistency | Value + `−`/`+` steppers (48 px) + tap-the-number-to-type | Steppers use `step`; typing opens the numeric keypad |
| `NoteField` | learned's note | One-line input, 400 char max, appears only when `learned` is `yes` | Inline, never a modal |
| `AutoCell` | strip | `label value` + source dot | Tap → a 200 px sheet with history, "source: watch", and an override |

**Interaction budget — the 2-tap rule.** Every manual metric is settleable in ≤ 2 interactions,
and the common case is 1. Anything needing 3+ interactions (date pickers, sliders, dropdowns) is
rejected.

**Write timing.** A tap writes optimistically in ≤ 16 ms, then persists (debounced 400 ms) and
syncs (debounced 2 s). The row shows a 1 px ink line drawing along its baseline over 180 ms; the
header number updates with no animation.

**Undo.** Last 20 writes are invertible. After each write a quiet toast appears bottom-left for
4 s: `Protein 3 — undo`. `⌘Z` also works. Never a modal, never a confirmation dialog.

## 4. Keyboard map (desktop)

| Key | Action |
|---|---|
| `Tab` / `Shift+Tab` | Move between rows (native tab order, one tab stop per row) |
| `J` / `K` | Move down / up |
| `1`–`7` | Set the focused row to its Nth option (`1` = first) |
| `Space` | Primary action: `✓` for tri-state, increment for numbers |
| `Backspace` | Clear the focused row to unset |
| `E` | Edit the note of the focused row (if it has one) |
| `⌘Z` / `Ctrl+Z` | Undo the last write |
| `G` then `T` / `W` / `R` / `S` | Today / Week / Trends / Settings |
| `[` / `]` | Previous / next logical day (day detail) |
| `Esc` | Dismiss sheet, blur input |
| `?` | Keyboard help overlay |

Focus ring: `2px solid var(--accent)` with `outline-offset: 2px`. Rows are `<fieldset role="radiogroup">`
with a visually hidden `<legend>`; cells are `<button role="radio" aria-checked>` or `<input type="radio">`
in a group. Screen readers must announce `Protein anchors, 3 of 5`.

- `=== ` markers use ink density, never colour alone.
- Tapping a day opens `/?d=…`.
- Weekly metrics show "met / on pace / behind" — pace is informational only and never affects the
  daily score (see `01-brief.md` §3.4).
- The comparison line always states the direction in words (`+6`, `−4`), not just an arrow.

## 6. Trends

- One sparkline row per metric: label, current value, 30/90 toggle, target hairline, and the
  metric's 30-day hit-rate. Rows are grouped by pillar with a small rule between groups.
- Above the list: up to five insight cards from `02-metrics.md` §6, each with its `n`.
- A 90-day consistency grid (7 columns, ink density, no green squares) under each pillar heading.
- Every chart is pure SVG. No tooltips on hover; tap selects a day and shows it in the line above
  the chart. No legends — the row label is the legend.

## 7. Settings

Grouped sections, all inline, no modals:

1. **Body** — bodyweight, protein g/kg, goal weight, weight mode, weekly weigh-in day.
2. **Targets** — one row per metric: current target, weight (0–2 slider-free numeric), visible toggle,
   and the `help` + `evidence` line in muted small text.
3. **Automation** — Apple Health, PC collector, sync: on/off, last received, and a `Test` button.
4. **Routine** — day cutoff hour, week starts on, evening prompt time.
5. **Data** — export JSON, export CSV, import JSON, delete everything (typed confirmation).
6. **Appearance** — light / dark / system; density comfortable / compact.
7. **Presets** — `gentle`, `standard`, `strict`. Strict raises targets (protein to 2.0 g/kg, social
   to 20 min, distraction to 60 min) and lowers floors. Presets only touch targets, never weights.

Settings changes are written immediately and re-score all history on the next render. A one-line
notice confirms: `Re-scoring 412 days.`

## 8. Onboarding (once, 9 fields, ≤ 3 min)

| Step | Ask | Default |
|---|---|---|
| 1 | Bodyweight (kg) | none — required |
| 2 | Protein per kg | 1.6 g/kg |
| 3 | Goal weight + mode (cut / maintain / bulk) | none / maintain |
| 4 | Gym sessions per week | 2 |
| 5 | Phone limit / social limit | 3 h / 30 min |
| 6 | Alcohol stance (zero / occasional) | zero |
| 7 | Sleep target | 7.5 h |
| 8 | Savings target | 20 % |
| 9 | Day cutoff + week start | 04:00 / Monday |

Then: `Log your first day →`. Skipping is possible; skipped values keep the registry defaults and
the app shows a muted `using default targets — review` line in Settings until visited.

## 9. States, empty, error, offline

| State | Behaviour |
|---|---|
| Empty day | Rows show unset controls. No illustration, no encouragement copy. |
| Fresh install | Straight into onboarding. Never show an empty dashboard. |
| Loading | Skeleton: the row labels render immediately, controls fade in over 120 ms. No spinner. |
| Offline | A muted word `offline` in the header. Writes queue. Never a blocking modal. |
| Sync error | One line under the header: `Not synced since 14:02 — retrying`. Tap to open Settings. |
| Sync conflict | Bottom sheet listing the conflicting fields; default resolution is last-write-wins per field; the user can flip any individual field. |
| Device gap ≥ 3 days | Banner: `Watch data missing for 4 days. Scores are less reliable.` Non-dismissible while active. |
| Insufficient data | `Not enough logged yet — the score appears after 25 % coverage.` |
| Corrupt local data | Restore from the last exported backup; show the path. Never silently wipe. |

## 11. Notifications and capture surfaces

- **In-app notifications: none.** No push, no reminders.
- **Evening prompt:** an iOS Shortcut personal automation at the configured time opens the PWA
  (`north://` is not available; use the Shortcut's "Open URLs" action). Recipe in `07-automation.md`.
- **NFC tags:** creatine jar, Kindle cover, gym bag. One tap fires a Shortcut that POSTs directly
  to the data repo without opening the app. Recipe in `07-automation.md`.
- **Home screen:** PWA, standalone display, paper background, no splash animation.

## 12. Accessibility requirements

- Complete keyboard operation of every screen and every widget.
- `aria-live="polite"` on the score header announcing `Today 82, up from 79`.
- `radiogroup` semantics for all cell rows; `aria-checked` reflects state.
- Contrast ≥ 4.5:1 for text, ≥ 3:1 for the target hairlines and focus rings.
- Never colour as the only signal: bands always carry a word, streaks carry a count.
- `prefers-reduced-motion` removes the ink-line animation and all transitions > 0 ms.
- Touch targets ≥ 44 × 44 px including padding.
- Zoom must not break layout up to 200 %.
